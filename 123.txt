Разработай полноценный современный веб-сервис под названием ToolRegs — универсальную платформу с большим количеством онлайн-инструментов для работы с изображениями, документами, PDF, видео, аудио, текстом, файлами, данными и различными полезными задачами.

Главная концепция проекта:

Один сайт, на котором пользователь может быстро найти нужный инструмент, загрузить или вставить данные и получить готовый результат без установки дополнительного ПО.

1. Технологии

Использовать:

PHP — основная серверная часть и API
HTML5
CSS3
JavaScript
Python — отдельные обработчики для задач, где PHP неудобен или требуются специализированные библиотеки
SQLite — основная база данных
REST API для взаимодействия frontend ↔ backend
AJAX / Fetch API
WebSocket или Server-Sent Events там, где это действительно необходимо для отображения прогресса долгих операций

Разрешается использовать сторонние библиотеки и Composer/Pip-пакеты.

Не использовать огромный frontend-фреймворк без необходимости. Основной интерфейс сделать на чистом HTML/CSS/JS либо с небольшими специализированными библиотеками.

2. Главный принцип архитектуры

Проект должен иметь модульную архитектуру.

Каждый инструмент должен быть отдельным независимым модулем.

Новый инструмент должен добавляться максимально просто:

Создать новую папку модуля.
Добавить описание инструмента.
Подключить backend/frontend.
Инструмент автоматически появляется в каталоге и поиске.

Не делать архитектуру, где весь проект находится в одном огромном index.php.

Каждый инструмент должен иметь собственные:

PHP-код;
Python-код, если требуется;
JavaScript;
CSS;
шаблон/HTML;
конфигурацию;
обработчики;
документацию.

4. Система модулей

Создать единый механизм регистрации инструментов.

Каждый инструмент должен иметь собственный manifest/config-файл.

Например:

tools/image/compress/


содержит:

manifest.json
index.php
handler.php
script.js
style.css
README.md


При запуске приложения система автоматически сканирует директорию tools/, находит manifest-файлы и регистрирует инструменты.

Таким образом, добавление нового инструмента не должно требовать ручного изменения главной страницы.

9. Ctrl + V

Для инструментов, работающих с изображениями, реализовать поддержку:

Ctrl + V


Пользователь должен иметь возможность скопировать изображение, например:

изображение из графического редактора;

и вставить его непосредственно в область инструмента.

JavaScript должен перехватывать paste и автоматически определять наличие изображения в Clipboard API.

После вставки изображение должно появляться в списке файлов без необходимости выбирать его через файловый диалог.

11. Прогресс обработки

Для долгих операций отображать:

14. Логирование

Логировать каждое значимое действие пользователя.

15. Временные файлы

Все загруженные пользователем файлы должны считаться временными.

Создать систему автоматической очистки:

storage/uploads/
storage/processed/
storage/temp/


Например:

загруженные файлы удалять через несколько часов;
обработанные файлы удалять через несколько часов;
временные файлы удалять значительно раньше.

Время хранения сделать настраиваемым через конфигурацию.

Создать cron-задачу:

php scripts/cleanup.php


которая очищает старые файлы и старые задачи.

20. API

Создать единый API для инструментов.

Пример:

POST /api/tools/{tool}/upload
POST /api/tools/{tool}/process
GET  /api/jobs/{job_id}
GET  /api/jobs/{job_id}/result
DELETE /api/files/{file_id}

API должно возвращать JSON.

Пример:

{

    "status": "queued"
}


Ошибки:

{
    "success": false,
    "error": "File is too large"

21. Работа с ошибками

Никогда не показывать пользователю PHP traceback или внутреннюю информацию сервера.

Пользователь должен получить:

Не удалось обработать файл.

Попробуйте ещё раз или выберите другой файл.


А подробная ошибка должна попасть в серверный лог.

22. Производительность

Проект должен быть рассчитан на большое количество инструментов.

Не загружать JS/CSS всех инструментов на каждой странице.

Загружать ресурсы конкретного инструмента только тогда, когда он открыт.

Не выполнять тяжёлые операции непосредственно внутри обычного HTTP-запроса, если операция может выполняться долго.

Использовать очередь задач для тяжёлых операций.

29. Результат

В результате должен получиться не набор отдельных скриптов, а единая расширяемая платформа онлайн-инструментов.

Пользователь заходит на главную страницу, видит поиск и категории, выбирает инструмент, загружает/вставляет файл, выполняет операцию и получает результат.

Система автоматически:

находит инструмент;
показывает его пользователю;
принимает файл;
проверяет безопасность;
создаёт задачу;
выполняет обработку;
показывает прогресс;
отдаёт результат;
записывает действие в лог;
удаляет временные файлы после истечения срока хранения.

При разработке сначала создать ядро платформы и систему модулей, а уже затем реализовывать отдельные инструменты.

Не делать каждый инструмент отдельным мини-сайтом.

Главная цель — создать архитектуру, которую можно расширять годами добавлением новых модулей.
